# Pipelines

A pipeline is a directed acyclic graph of named nodes, written in a TOML file. Each
node has a kind (`type`), parameters (`params`) and the names of the nodes it reads
from (`inputs`). `tptbio pipeline run` validates the file and runs it. The same
definitions can be loaded from the library crate `tpt-bio-pipeline`.

This tutorial uses inputs generated by the examples in this repository. It has three
parts: a statistics pipeline, an image pipeline and a sequence pipeline.

## 1. The file format

```toml
[[nodes]]
name = "table"                  # unique name, used by other nodes
type = "table_source"           # node kind, listed in section 2
params = { values = [[0.0, 0.0], [0.0, 1.0], [10.0, 10.0], [10.0, 11.0]] }

[[nodes]]
name = "scaled"
type = "normalize"
params = { method = "zscore" }
inputs = ["table"]              # the nodes whose outputs this node reads
```

Rules that the loader enforces:

- Each `name` is unique. An `inputs` entry must name an existing node.
- Inputs are matched to the kind's input ports in order. `watershed` takes
  `["image", "markers", "mask"]`, so the order matters.
- Types must match: a `write_frame_csv` node needs a `frame` input, which only
  `measure` produces.
- Parameters are checked against the kind. Unknown kinds, missing required parameters
  and cycles are errors, reported before anything runs.

## 2. Node kinds

| Kind | Inputs | Output | Parameters |
| --- | --- | --- | --- |
| `table_source` | none | table | `values` (rectangular array of numbers) |
| `normalize` | table | table | `method` (`zscore` or `robust`) |
| `pca` | table | table | `components` |
| `kmeans` | table | labels | `k`, `seed`, `max_iter` |
| `frame_to_table` | frame | table | `columns` |
| `read_fastq` | none | fastq | `path` |
| `read_bam` | none | records | `path` |
| `count_reads` | fastq | table | none |
| `count_records` | records | table | none |
| `count_objects` | objects | table | none |
| `write_records_csv` | records | file | `path` |
| `write_frame_csv` | frame | file | `path` |
| `write_labels_csv` | labels | file | `path` |
| `load_image` | none | image | `path`, `channel` |
| `gaussian` | image | image | `sigma` |
| `subtract_background` | image | image | `radius` |
| `otsu` | image | mask | `bins` |
| `label` | mask | objects | `connectivity` (4 or 8) |
| `filter_objects` | objects | objects | `min_area`, `max_area`, `remove_border` |
| `log_seeds` | image | objects | `sigma`, `min_distance`, `min_response` |
| `watershed` | image, objects, mask | objects | none |
| `measure` | objects, image | frame | none |

The image kinds work on 2D images only. `read_fastq` and `read_bam` read whole files
into memory. The stream and checkpoint modules of `tpt-bio-pipeline` are library
features and are not reachable from TOML.

## 3. Run a statistics pipeline

Save this as `stats.toml`:

```toml
[[nodes]]
name = "table"
type = "table_source"
params = { values = [[0.0, 0.0], [0.0, 1.0], [10.0, 10.0], [10.0, 11.0]] }

[[nodes]]
name = "scaled"
type = "normalize"
params = { method = "zscore" }
inputs = ["table"]

[[nodes]]
name = "reduced"
type = "pca"
params = { components = 1 }
inputs = ["scaled"]

[[nodes]]
name = "groups"
type = "kmeans"
params = { k = 2, seed = 1 }
inputs = ["reduced"]
```

Run it:

```sh
tptbio pipeline run stats.toml
```

Tables are printed as CSV with columns `c1`, `c2`, and so on. Labels print a
summary line (`labels: 4 rows, 2 clusters`). Every output, in definition order, is
printed. Images, masks and objects print a one-line summary.

## 4. Run an image pipeline

First generate the input image with the vision example (see the vision tutorial).
It writes `vision-demo/scene.png`. Then save this as `vision.toml`:

```toml
[[nodes]]
name = "scene"
type = "load_image"
params = { path = "vision-demo/scene.png", channel = 0 }

[[nodes]]
name = "smooth"
type = "gaussian"
params = { sigma = 1.0 }
inputs = ["scene"]

[[nodes]]
name = "foreground"
type = "otsu"
inputs = ["smooth"]

[[nodes]]
name = "labelled"
type = "label"
params = { connectivity = 8 }
inputs = ["foreground"]

[[nodes]]
name = "objects"
type = "filter_objects"
params = { min_area = 10, remove_border = true }
inputs = ["labelled"]

[[nodes]]
name = "features"
type = "measure"
inputs = ["objects", "smooth"]

[[nodes]]
name = "features_csv"
type = "write_frame_csv"
params = { path = "vision-demo/pipeline-objects.csv" }
inputs = ["features"]
```

Run it from the repository root:

```sh
tptbio pipeline run vision.toml
head -n 3 vision-demo/pipeline-objects.csv
```

The CSV has one row per object with shape and intensity columns, the same as
`tptbio vision features`.

## 5. Run a sequence pipeline

Generate a small sorted BAM, then count and export its records:

```sh
printf '@HD\tVN:1.6\n@SQ\tSN:chr1\tLN:100000\n' > pipe-reads.sam
for i in $(seq 1 50); do
  printf 'read%03d\t0\tchr1\t%d\t60\t20M\t*\t0\t0\tACGTACGTACGTACGTACGT\tIIIIIIIIIIIIIIIIIIII\n' "$i" $(( i * 997 % 90000 + 1 )) >> pipe-reads.sam
done
tptbio seq sort pipe-reads.sam -o pipe-reads.bam
```

Save this as `seq.toml`:

```toml
[[nodes]]
name = "alignments"
type = "read_bam"
params = { path = "pipe-reads.bam" }

[[nodes]]
name = "count"
type = "count_records"
inputs = ["alignments"]

[[nodes]]
name = "export"
type = "write_records_csv"
params = { path = "pipe-records.csv" }
inputs = ["alignments"]
```

```sh
tptbio pipeline run seq.toml
head -n 2 pipe-records.csv
```

## 6. Run from Rust

The example `tpt-bio-pipeline/examples/pipeline_quickstart.rs` parses the statistics
pipeline from a string, runs it, and then runs a plain `Dag` with the parallel executor:

```sh
cargo run -p tpt-bio-pipeline --example pipeline_quickstart
```

The core calls are:

```rust
let pipeline = Pipeline::from_toml(STATS)?;
for (i, value) in pipeline.run()?.iter().enumerate() {
```

`Pipeline::run` returns one `Value` per node, in definition order. `Value` has the
variants `Table`, `Labels`, `Fastq`, `Records`, `File`, `Image`, `Mask`, `Objects` and
`Frame`.

## 7. The spec section 7 flow

`tpt-bio-pipeline/examples/spec7_screen.toml` implements steps 1 to 6 of the
high-content screening example in `spec.txt`, on 2D images. It reads from `screen/`.
Create that directory with a copy of the generated image, then run it from the
directory that contains `screen/`:

```sh
mkdir -p screen && cp vision-demo/scene.png screen/plate.png
tptbio pipeline run tpt-bio-pipeline/examples/spec7_screen.toml
```

It writes `screen/features.csv` and `screen/phenotypes.csv`. Note that the file reads
`screen/` relative to the current directory, and that the 50 GB S3 input and 3D blur
in the spec are not implemented (see the README).

## Limits

- Execution is in memory and runs nodes one after another. The library's
  `execute_parallel` runs independent nodes at the same time, but `Pipeline::run`
  uses the sequential executor.
- The TOML kinds cover BAM and FASTQ input, and CSV output. There are no VCF or BCF
  kinds, and no image writers.
- Checkpointing (`tpt_bio_pipeline::checkpoint`) and the bounded stream (`stream`) are
  library APIs only.
